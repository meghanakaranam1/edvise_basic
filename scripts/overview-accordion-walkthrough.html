What to check:
• Course Failure has a ▶ because it's made of two signals in your data — Math Grade and English Grade. Click it: it expands to show each one's own count/%, instead of only one blended "Course Failure" number.
• The (any flag) tag next to the category name is the plain-language cue that this isn't "only English" or "only Math" — a student counts toward Course Failure if either one applies. No overlap math shown; Math + English won't sum exactly to the parent total, and that's expected, not something that needs explaining inline.
• Chronic Absence and Suspensions have no ▶ here because each currently comes from a single signal — nothing to break out. If a dataset had e.g. two attendance signals (Q1 + Q2), that row would get a ▶ too.
• Click a stat tile ("Any flag," "All 3 flags," etc.) — instead of an inline table, it appends a simulated chat exchange below the card: a user-style message asking for that roster, a typing indicator, then the actual roster table as an assistant reply. That mirrors how the real app's existing roster/export feature already works (runs real code execution against your file, not a canned inline filter), rather than inventing a new UI pattern.
